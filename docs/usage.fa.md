# راهنمای استفاده از Patch Desk

## شروع سریع

پنل را در `http://127.0.0.1:8765` باز کنید. در نصب لینوکس، ابتدا SSH tunnel معرفی‌شده در [راهنمای نصب](installation.fa.md) را برقرار کنید.

1. هر IP یا hostname را در یک خط وارد کنید.
2. یک تا چهار پورت واقعی SSH را بدهید؛ مثلاً `22,2222,2200,2022`.
3. کاربران پیش‌فرض `root` و `rooot` هستند. اگر لازم است آن‌ها را تغییر دهید؛ کاربر دوم اختیاری است.
4. یک تا سه رمز شناخته‌شده را وارد کنید. در بخش «رمزهای سرورها متفاوت‌اند؟»، برای هر IP رمز اختصاصی بدهید؛ فیلد اختصاصی خالی از رمزهای مشترک استفاده می‌کند.
5. برای شروع آزمایشی، هم‌زمانی را روی یک بگذارید. مقدار یک، به ترتیب لیست پیش می‌رود؛ حداکثر شش قابل انتخاب است. اعضای یک خوشه را هم‌زمان آپدیت نکنید.
6. «افزودن و شروع خودکار» را بزنید. این دکمه اجازه اجرای آپدیت موردنیاز و restart سرویس مربوط است؛ تأیید دوباره برای هر سرور ندارد.

```text
192.0.2.10
192.0.2.11:2222|2200
192.0.2.12,22|2222,root,rooot
[2001:db8::10]:2222
```

پورت موفق در اتصال بعدی اولویت دارد. پورت بسته یا بدون پاسخ برای همه رمزها تکرار نمی‌شود. حداکثر چهار پورت پاسخگو، دو کاربر و سه رمز می‌توانند ۲۴ ترکیب ورود بسازند؛ سیاست قفل حساب سرور همچنان اعمال می‌شود. این ابزار رمز کشف نمی‌کند و اسکن آزاد پورت ندارد.

## نتیجه هر سرور

| نتیجه | معنی / کار بعدی |
|---|---|
| اوکی؛ آپدیت لازم نیست | PHPهای شناسایی‌شده شواهد اصلاح این دو CVE را دارند؛ فرمان آپدیت اجرا نشده است. |
| آپدیت شد؛ اوکی | عملیات به‌روزرسانی انجام و شواهد نسخه اصلاح‌شده ثبت شده است. |
| PHP شناسایی نشد | PHP در مسیرها و کانتینرهای بررسی‌شده پیدا نشده؛ نه خطای آپدیت است و نه گواهی نبود نصب سفارشی. |
| اتصال SSH برقرار نشد | پورت‌ها، روشن‌بودن میزبان، فایروال و مسیر/VPN بررسی شوند؛ PHP هنوز بررسی نشده است. |
| SSH پاسخ داد؛ رمز پذیرفته نشد | کاربر، رمز یا مجازبودن ورود با رمز باید بررسی شود. |
| کاربر مجوز sudo ندارد | با root یا حساب دارای مجوز مدیریتی وصل شوید؛ ابزار sudoers را تغییر نمی‌دهد. |
| هنوز نسخه امن تأیید نشد | بسته یا image اصلاح‌شده در دسترس نبوده یا شواهد کافی نیست؛ موفقیت دستور آپدیت به‌تنهایی کافی نیست. |
| تنظیم نصب بررسی شود | مسیر نصب سفارشی یا هویت پروژه Compose قابل‌شناسایی نیست. |

جدول «عملیات و شواهد اجرا» علت و قدم بعدی را مستقیم نشان می‌دهد. جزئیات فنی برای مشاهده فرمان و خروجی مرحله بازشدنی است. پیش از بستن برنامه، گزارش JSON را دریافت کنید؛ تاریخچه در حافظه نگه‌داری می‌شود.

## حذف گروهی

در فهرست سرورها، مربع بالای ستون انتخاب را بزنید تا همه موارد آماده انتخاب شوند، سپس «حذف انتخاب‌شده‌ها» و تأیید را بزنید. می‌توانید فقط چند سرور را هم انتخاب کنید.

این کار فقط رکورد اتصال، رمزهای حافظه و برنامه آماده آن‌ها را حذف می‌کند؛ هیچ کاری روی سرور لینوکسی انجام نمی‌دهد. گزارش‌های قبلی باقی می‌مانند. اگر یکی از انتخاب‌ها مشغول یا در صف باشد، کل درخواست حذف رد می‌شود و هیچ رکوردی حذف نمی‌شود. برای حذف گزارش‌های قبلی از نشست، برنامه را پس از پایان همه کارها ببندید؛ فایل‌های گزارشِ دریافت‌شده جدا هستند.

## مسیر دستی پنل

با «افزودن تکی»، اتصال جدا ثبت کنید. «بررسی» وضعیت را می‌خواند و «نتیجه» توضیح ساده و شواهد را نشان می‌دهد. پورت‌های رکورد قبلی از «اتصال» قابل تغییرند. برای به‌روزرسانی دستی انتخاب‌ها، دامنه PHP/همه بسته‌ها/Compose را انتخاب و «به‌روزرسانی انتخاب‌ها» را بزنید؛ برنامه نهایی را بخوانید و سپس شروع کنید. مسیر دستی تأیید داشتن backup را می‌خواهد.

URL سلامت اختیاری از روی همان سرور، قبل و بعد از تغییر، با curl بررسی می‌شود. موفقیت HTTP جای تست همه کارکردهای برنامه نیست. حالت «همه بسته‌ها» ممکن است سرویس‌های دیگری را restart کند؛ ارتقای نسخه توزیع نیست.

## Mirror، Docker و محدودیت‌ها

مخزن فعلی اولویت دارد. fallback موقت رسمی برای نسخه‌های پشتیبانی‌شده در صورت خطای قابل‌تشخیص فعال می‌شود؛ TLS و امضای بسته خاموش نمی‌شوند. مخزن رسمی لزوماً بسته PHP شخص ثالث را ندارد. تغییر stream، downgrade، پاک‌کردن قفل، `allowerasing` و reboot خودکار انجام نمی‌شود.

Compose از برچسب کانتینرهای جاری شناسایی و همان project/file/service استفاده می‌شود. `pull` و جایگزینی همان سرویس انجام می‌شود؛ image سفارشی rebuild و tag قدیمی خودکار اصلاح نمی‌شود. نبود healthcheck، کانتینر متوقف، Kubernetes، کنترل‌پنل و PHP در مسیر سفارشی ممکن است به بررسی جداگانه نیاز داشته باشند.

رمز sudo همان رمز ورود موفق است. رمزها فقط در حافظه‌اند و پس از restart برنامه باید دوباره وارد شوند. کلید SSH، حتی اگر تغییر کرده باشد، مطابق رفتار فعلی برنامه خودکار پذیرفته می‌شود؛ از شبکه و مقصد مطمئن استفاده کنید. توقف از مرز مراحل اعمال می‌شود؛ مدیر بسته جاری قطع نمی‌شود. قبل از تکرار عملیاتِ قطع‌شده، وضعیت سرور را بررسی کنید.
