# نصب Patch Desk

این برنامه یک کنترل‌کننده مرکزی است؛ لازم نیست روی تمام سرورهای مقصد نصب شود. کنترل‌کننده باید به SSH مقصدها و مخازن موردنیاز دسترسی داشته باشد. اینستالر فقط خود پنل را نصب می‌کند و هیچ سرور مقصدی را آپدیت نمی‌کند.

## اینستالر Linux / systemd

کنترل‌کننده پشتیبانی‌شده: Ubuntu 24.04 تا 26.x، Debian 12/13 و AlmaLinux 9/10 با systemd و دسترسی sudo. مقصدها می‌توانند نسخه‌های دیگری باشند که موتور برنامه پشتیبانی می‌کند. Python 3.11 یا جدیدتر لازم است؛ روی AlmaLinux 9، Python 3.11 جداگانه نصب می‌شود.

پس از clone یا دریافت سورس:

```bash
cd patch-desk
bash install.sh --dry-run
sudo bash install.sh
sudo systemctl status patch-desk
```

اینستالر، پیش‌نیازهای Python را از مخزن فعلی توزیع نصب، کاربر غیرممتاز `patchdesk` را ایجاد، فقط فایل‌های مجاز سورس را کپی و وابستگی‌ها را از `requirements-lock.txt` نصب می‌کند. فایل داده یا گزارش checkout منتقل نمی‌شود.

| مسیر | کاربرد |
|---|---|
| `/opt/patch-desk` | سورس و محیط Python؛ متعلق به root و برای سرویس فقط خواندنی |
| `/var/lib/patch-desk` | مشخصات اتصال و state؛ متعلق به patchdesk، با دسترسی محدود |
| `/etc/systemd/system/patch-desk.service` | سرویس systemd |

پنل فقط روی `127.0.0.1:8765` گوش می‌دهد. از رایانه خودتان تونل بزنید:

```bash
ssh -N -L 8765:127.0.0.1:8765 USER@CONTROLLER
```

اگر SSH کنترل‌کننده پورت دیگری دارد، `-p PORT` اضافه کنید. سپس مرورگر را روی `http://127.0.0.1:8765` باز کنید. برای پورت محلی متفاوت، مثلاً `-L 8877:127.0.0.1:8765`، مرورگر را روی پورت 8877 باز کنید.

این نسخه نشست مدیریتی مشترک دارد؛ هرکس به پورت loopback کنترل‌کننده یا تونل آن دسترسی دارد، می‌تواند پنل را باز کند. پنل را با bind عمومی یا reverse proxy بدون احراز هویت منتشر نکنید. اینستالر هیچ پورت عمومی در فایروال باز نمی‌کند.

## مدیریت سرویس

```bash
sudo systemctl status patch-desk
sudo journalctl -u patch-desk -n 80 --no-pager
# فقط بعد از پایان تمام عملیات:
sudo systemctl restart patch-desk
```

restart، رمزها و تاریخچه حافظه را پاک می‌کند. مشخصات غیرمحرمانه اتصال در پوشه state باقی می‌مانند. قبل از restart گزارش را دریافت کنید. اینستالر fresh-install است و وجود پوشه، state، کاربر یا unit قبلی را بررسی می‌کند؛ اطلاعات قبلی را بازنویسی یا حذف نمی‌کند. اگر نصب نیمه‌کاره بود، پیام خطا و journal را بررسی کنید؛ برای پاک‌سازی، پوشه‌ها را کورکورانه حذف نکنید.

## ارتقای نسخه نصب‌شده

اینستالر را دوباره روی نصب موجود اجرا نکنید. پس از تمام‌شدن عملیات و دریافت گزارش، از `/var/lib/patch-desk` و سورس نسخه قبلی backup بگیرید، سرویس را متوقف و نسخه جدید را در checkout جداگانه تست کنید. همان فایل‌های allowlist اینستالر را به نصب منتقل کنید، وابستگی‌ها را با interpreter محیط نصب به‌روز و سرویس را دوباره راه بیندازید. rollback سورس، نصب بسته‌های انجام‌شده روی سرور مقصد را برنمی‌گرداند.

## اجرای دستی / Windows

```powershell
.\Start.ps1
```

یا روی هر سیستم دارای Python 3.11+:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python app.py
```

در Windows، interpreter برابر `.venv\Scripts\python.exe` است. پورت با `PATCH_DESK_PORT` و مسیر داده با `PATCH_DESK_DATA_DIR` قابل تنظیم است؛ برنامه همچنان فقط روی loopback گوش می‌دهد.

## اعتبارسنجی

تست‌های پروژه و بررسی syntax/dry-run اینستالر از نصب واقعی روی توزیع‌های مختلف جدا هستند. تا ثبت نتیجه نصب واقعی، پشتیبانی اعلام‌شده را دستورالعمل و مسیر پیاده‌شده بدانید، نه تضمین سازگاری همه نصب‌ها. CI لینوکس نیز برای تست خودکار پروژه در رپو قرار دارد.
