از ورود IP تا بررسی نتیجه

این ابزار روی سرورهای خودتان با SSH کار می‌کند. قبل از شروع backup داشته باشید؛ دکمه شروع خودکار می‌تواند بسته PHP را نصب و سرویس را restart کند.

شروع کارمعنی نتیجه‌هاحذف گروهیپچ دستی PHPاتصال و رمزها

شروع کار

  1. هر IP را در یک خط وارد کنید. برای پورت متفاوت از IP:2222|2200 استفاده کنید.
  2. حداکثر چهار پورت واقعی بدهید؛ مثلاً 22,2222,2200,2022.
  3. کاربران پیش‌فرض root و rooot هستند. رمزهای شناخته‌شده را وارد کنید. برای رمز متفاوت هر سرور، بخش مربوط را باز و فیلدها را بسازید.
  4. هم‌زمانی یک یعنی بررسی به ترتیب لیست. برای شروع از یک سرور آزمایشی استفاده کنید.
  5. «افزودن و شروع خودکار» بررسی را آغاز می‌کند؛ سرور به‌روز تغییری نمی‌کند و سرور نیازمند آپدیت وارد عملیات می‌شود.
192.0.2.10
192.0.2.11:2222|2200
192.0.2.12,22|2222,root,rooot

پیاممعنی
اوکی؛ آپدیت لازم نیستPHPهای شناسایی‌شده شواهد اصلاح دارند؛ دستور آپدیت اجرا نشده است.
آپدیت شد؛ اوکیآپدیت انجام و نسخه اصلاح‌شده ثبت شده است.
PHP شناسایی نشددر مسیرهای بررسی‌شده PHP پیدا نشده؛ نصب سفارشی هنوز ممکن است.
اتصال SSH برقرار نشدپورت، فایروال، مسیر/VPN یا روشن‌بودن میزبان بررسی شود؛ PHP هنوز بررسی نشده است.
کاربر مجوز sudo ندارداز root یا حساب دارای مجوز استفاده کنید؛ برنامه مجوز اضافه نمی‌کند.
هنوز نسخه امن تأیید نشدmirror، بسته یا image ممکن است هنوز نسخه اصلاح‌شده نداشته باشد؛ صرف موفقیت دستور کافی نیست.

علت و قدم بعدی در جدول عملیات است. برای فرمان و خروجی، جزئیات فنی را باز کنید. پیش از بستن برنامه، گزارش JSON بگیرید.

حذف همه یا چند سرور

مربع بالای فهرست را بزنید تا همه موارد آماده انتخاب شوند؛ سپس «حذف انتخاب‌شده‌ها» و تأیید را بزنید. برای چند مورد، فقط همان‌ها را انتخاب کنید.

این کار فقط فهرست اتصال، رمز حافظه و برنامه آماده را حذف می‌کند؛ روی Linux مقصد تغییری نمی‌دهد. گزارش‌های قبلی باقی می‌مانند. اگر یکی از موارد مشغول یا در صف باشد، کل حذف رد می‌شود.

پچ دستی PHP

برای CVE-2026-109618 و CVE-2026-109619، نسخه‌های اصلاح‌شده upstream برابر 8.2.35، 8.3.36، 8.4.27 و 8.5.12 هستند. بسته vendor دارای backport معتبر ممکن است شماره قدیمی‌تری داشته باشد. اطلاعیه رسمی PHP

  1. سیستم‌عامل، شاخه PHP، مخزن و سرویس فعال را پیدا کنید.
  2. در Ubuntu/Debian فقط بسته‌های نصب‌شده را به‌روز کنید؛ ابتدا تغییرات را simulate کنید.
  3. در Alma/Remi، stream فعلی را حفظ و فقط بسته‌های PHP نصب‌شده را upgrade کنید.
  4. سرویس FPM یا Apache واقعاً استفاده‌شده را restart کنید.
  5. نسخه کامل بسته، PHP داخل Docker و سلامت برنامه را بررسی کنید.
cat /etc/os-release
php -v
systemctl list-units --type=service --state=running --no-pager

مثال Ubuntu برای بسته‌هایی که از قبل نصب‌اند؛ نام شاخه و بسته را با نصب خود تطبیق دهید:

sudo apt-get update -o APT::Update::Error-Mode=any
sudo apt-get --simulate --no-remove --only-upgrade install php8.1-cli php8.1-common
sudo apt-get --no-remove --only-upgrade install php8.1-cli php8.1-common

این دو بسته فقط مثال‌اند؛ همه بسته‌ها و workerهای PHP نصب خود را در راهنمای کامل بررسی کنید. در Docker باید image اصلاح‌شده دریافت/ساخته و سرویس جایگزین شود؛ آپدیت میزبان کافی نیست.

بازکردن آموزش کامل پچ دستی: Ubuntu، Debian، Alma/Remi و Docker

اتصال، رمز و توقف

رمز sudo همان رمز ورود موفق است. رمزها فقط در حافظه‌اند و پس از restart دوباره وارد می‌شوند. کلید SSH، حتی کلید تغییرکرده، خودکار پذیرفته می‌شود؛ به مقصد و مسیر شبکه مطمئن نیاز دارید.

پورت موفق اولویت دارد. چند تلاش ناموفق ممکن است حساب را قفل کند. توقف در مرز مراحل اعمال می‌شود و مدیر بسته جاری قطع نمی‌شود. قبل از تکرار کار قطع‌شده، وضعیت سرور را بررسی کنید. پنل چندکاربره نیست؛ برای نصب سروری از SSH tunnel استفاده کنید.
