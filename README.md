# PatchHarbor — بندر امن به‌روزرسانی سرورها

پنل فارسی برای ثبت گروهی سرورهای Linux، اتصال SSH با چند پورت/کاربر/رمز، بررسی PHP و اجرای به‌روزرسانی فقط در صورت نیاز. رابط RTL است و علت خطا و قدم بعدی را به زبان ساده نشان می‌دهد.

> نسخه اولیه عملیاتی است؛ نتیجه PHP فقط نصب‌های شناسایی‌شده و قواعد ثبت‌شده را پوشش می‌دهد. نصب controller، وصله‌کردن سرورهای مقصد و تأیید سلامت برنامه سه کار متفاوت‌اند.

## نصب سریع

### Linux / systemd

کنترل‌کننده: Ubuntu 24.04–26.x، Debian 12/13 یا AlmaLinux 9/10، با systemd و sudo.

```bash
git clone https://github.com/8mafia/PatchHarbor.git
cd PatchHarbor
bash install.sh --dry-run
sudo bash install.sh
```

از رایانه خودتان:

```bash
ssh -N -L 8765:127.0.0.1:8765 USER@CONTROLLER
```

سپس [پنل محلی](http://127.0.0.1:8765) را باز کنید. اینستالر فقط controller را نصب می‌کند و هیچ مقصدی را آپدیت نمی‌کند. سرویس روی loopback می‌ماند؛ فایروال عمومی باز نمی‌شود. جزئیات مسیرها، مدیریت سرویس و محدودیت‌ها: [راهنمای نصب](docs/installation.fa.md).

### Windows

Python 3.11+ لازم است:

```powershell
.\Start.ps1
```

### اجرای دستی با Python

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python app.py
```

در Windows از `.venv\Scripts\python.exe` استفاده کنید. `PATCH_DESK_PORT` پورت و `PATCH_DESK_DATA_DIR` محل داده را تغییر می‌دهد؛ bind همچنان loopback است.

## استفاده

1. لیست IP/hostname را بدهید؛ هر خط یک سرور.
2. یک تا چهار پورت، دو کاربر و حداکثر سه رمز شناخته‌شده وارد کنید. پیش‌فرض کاربران `root` و `rooot` است. رمز sudo همان رمز ورود موفق است.
3. اگر رمزها متفاوت‌اند، فیلد رمز اختصاصی هر IP را از بخش مربوط بسازید.
4. «افزودن و شروع خودکار» را بزنید. بررسی به ترتیب لیست شروع می‌شود؛ هم‌زمانی یک تا شش قابل تنظیم است.
5. جدول نتیجه را ببینید: اوکی، آپدیت شد، PHP شناسایی نشد، خطای اتصال، sudo یا مخزن. قبل از خروج گزارش JSON بگیرید.

```text
192.0.2.10
192.0.2.11:2222|2200
192.0.2.12,22|2222,root,rooot
[2001:db8::10]:2222
```

پورت‌های مشترک مثال: `22,2222,2200,2022`. فقط پورت‌های واردشده امتحان می‌شوند و ترکیب موفق در اتصال بعدی اولویت دارد. با چهار پورت پاسخگو، دو کاربر و سه رمز، حداکثر ۲۴ ترکیب ورود ممکن است؛ سیاست قفل حساب مقصد را در نظر بگیرید.

### حذف گروهی

مربع بالای فهرست را بزنید، سپس «حذف انتخاب‌شده‌ها». حذف فقط رکورد اتصال، رمز حافظه و برنامه آماده را پاک می‌کند؛ روی Linux مقصد اثری ندارد. گزارش قبلی باقی می‌ماند. انتخاب سرور مشغول/در صف، کل حذف را متوقف می‌کند و حذف جزئی انجام نمی‌شود.

[راهنمای کامل استفاده](docs/usage.fa.md) از لینک **«راهنمای استفاده و پچ دستی»** داخل پنل هم در دسترس است.

## پچ دستی CVEهای PHP

[آموزش مرحله‌به‌مرحله پچ دستی](docs/manual-patching.fa.md) شامل این موارد است:

- تشخیص نسخه کامل بسته و تفاوت PHP میزبان، FPM، Apache و Docker؛
- شبیه‌سازی و نصب به‌روزرسانی بسته‌های از قبل نصب‌شده در Ubuntu/Debian و Alma/Remi؛
- restart سرویس صحیح و بررسی نتیجه؛
- image سفارشی و Compose؛
- خطاهای mirror، DNS، TLS، امضا، sudo و مدیر بسته.

منابع اصلی: [اطلاعیه PHP](https://www.php.net/archive/2026.php)، [USN-8948-1](https://ubuntu.com/security/notices/USN-8948-1)، [Debian security tracker](https://security-tracker.debian.org/tracker/CVE-2026-109619). قواعد پروژه snapshot مورخ ۲۱ اکتبر ۲۰۲۶ هستند، نه feed زنده vendor. بسته قدیمیِ دارای backport معتبر ممکن است اصلاح‌شده باشد؛ موفقیت package manager به‌تنهایی تأیید رفع CVE نیست.

## دامنه و رفتار

| بخش | رفتار |
|---|---|
| میزبان | Ubuntu، Debian و AlmaLinux؛ آپدیت PHP یا مسیر دستی همه بسته‌ها؛ ارتقای release و reboot ندارد. |
| Docker | کانتینر جاری، PHP در PATH و project/file/service قابل‌شناسایی Compose؛ حفظ هویت پروژه. |
| image سفارشی | rebuild و تغییر tag قدیمی خودکار ندارد؛ نسخه قدیمی بعد از pull، «اوکی» نمی‌شود. |
| mirror | مخزن فعلی اولویت دارد؛ fallback رسمی موقت برای releaseهای مشخص، بدون بازنویسی تنظیم mirror و بدون حذف TLS/امضا. |
| خطا | اتصال، احراز هویت، sudo، DNS، TLS، امضا، lock، دیسک و وابستگی جدا گزارش می‌شوند. |
| توقف | در مرز مراحل؛ مدیر بسته جاری قطع نمی‌شود. |
| نسخه نامشخص | بدون شواهد معتبر، ایمنی اعلام نمی‌شود؛ نبود PHP نتیجه مستقل دارد. |

نصب سفارشی، کنترل‌پنل، Kubernetes و کانتینر متوقف پوشش تضمین‌شده ندارند. fallback رسمی لزوماً PHP شخص ثالث را ندارد. sudoers، stream و کلید ناشناخته خودکار تغییر نمی‌کنند. rollback کامل، زمان‌بندی و بازیابی خودکار job پس از crash وجود ندارد. قبل از عملیات backup مستقل داشته باشید.

## مدل دسترسی و اطلاعات

- **کلید SSH خودکار پذیرفته می‌شود، حتی پس از تغییر.** این رفتار بررسی مستقل هویت را حذف می‌کند؛ در شبکه و مقصد مطمئن استفاده کنید.
- پنل یک نشست مشترک مدیریتی دارد؛ token نشست و کنترل Origin جای احراز هویت چندکاربره را نمی‌گیرند. هرکس به loopback/tunnel کنترل‌کننده دسترسی دارد می‌تواند پنل را باز کند. آن را عمومی منتشر نکنید.
- SSH/sudo password فقط در RAM است و در آرگومان فرمان، JSON یا فایل ذخیره نمی‌شود؛ پس از restart دوباره وارد کنید.
- آدرس/پورت/کاربر/اثر انگشت در پوشه داده می‌مانند. تاریخچه RAM است؛ پیش از خروج گزارش بگیرید.
- گزارش می‌تواند IP، image، مسیر و خروجی ابزارهای شخص ثالث داشته باشد؛ پیش از اشتراک‌گذاری بازبینی کنید. `.env` و Docker environment عمداً خوانده نمی‌شوند.
- state، گزارش‌های واقعی، screenshotهای نشست و یادداشت‌های محلی در Git نادیده گرفته می‌شوند. حذف فایل محلی با حذف از تاریخچه Git یکسان نیست؛ قبل از push فایل‌های stageشده را بررسی کنید.

## توسعه و تست

```bash
.venv/bin/python -m pytest -q
node tests/test_frontend.cjs
bash -n install.sh
bash install.sh --dry-run
```

تست‌ها از fixtureهای موقت و SSH loopback بدون اجرای shell واقعی استفاده می‌کنند؛ جای آزمون package manager و Compose روی VM واقعی را نمی‌گیرند. CI پروژه تست‌های Linux را اجرا می‌کند. فایل `static/FONT-LICENSE.txt` مجوز OFL فونت bundled Vazirmatn است.

## فایل‌های اصلی

`app.py`: API، state و صف · `engine.py`: SSH، شناسایی و برنامه عملیات · `reporting.py`: بازخوانی شواهد · `static/`: پنل و راهنما · `install.sh`: نصب کنترل‌کننده · `docs/`: آموزش‌ها.
